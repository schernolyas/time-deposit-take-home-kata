# CLAUDE.md — project rules for AI coding agents

This file is loaded automatically by Claude Code (and by Claude in other
surfaces that read `CLAUDE.md`). It is the single source of truth for how an
AI agent must work in this repository. Humans: read it too, it doubles as the
contribution guide.

## What this repository is

XA Bank time-deposit take-home kata. The solution lives in `java/`
(the other language folders are the untouched originals from the kata).

- Java 17 (do not use language features above 17), Maven, Spring Boot 3.5.
- Hexagonal architecture (ports & adapters).
- PostgreSQL + Spring Data JPA/Hibernate (`ddl-auto=validate`), schema owned by Flyway; integration tests run on Testcontainers.
- REST API is **contract-first**: `java/src/main/resources/static/openapi/time-deposit-api.yaml`
  is the source; Java interfaces and DTOs are generated by `openapi-generator-maven-plugin`.

## Hard constraints (never break these)

1. `org.ikigaidigital.TimeDeposit` is a shared class: no breaking changes
   (no removed/renamed members, no changed constructor or method signatures).
2. `TimeDepositCalculator.updateBalance(List<TimeDeposit>)` keeps its signature
   **and its exact numeric behaviour**, including:
   - annual rate divided by 12 in `double` arithmetic (`balance * rate / 12`);
   - interest rounded with `new BigDecimal(double).setScale(2, HALF_UP)`;
   - boundaries: all plans `days > 30`, student `days < 366`, premium `days > 45`;
   - unknown plan type → zero interest.
   `TimeDepositCalculatorCharacterizationTest` (golden master against
   `LegacyTimeDepositCalculator`) must stay green. Never edit the legacy copy.
3. Exactly **two** HTTP endpoints. Do not add endpoints (actuator web endpoints included).
4. Dependency rule: `org.ikigaidigital` (shared classes) and `..domain..` must not depend on Spring, on adapters
   or on config. `..application..` may use only Spring stereotypes, `@Primary` and `@Transactional`.
   JPA/Hibernate types never leave `adapter.out.persistence`; never annotate domain classes.
   `ArchitectureTest` enforces this.

## Package map

| Package | Role |
|---|---|
| `org.ikigaidigital` | shared legacy classes `TimeDeposit`, `TimeDepositCalculator`, Spring Boot main class |
| `org.ikigaidigital.domain` | `Withdrawal`, interest policies (`domain.interest`) |
| `org.ikigaidigital.application` | use cases (`port.in`), repositories and lock (`port.out`), `@Service` + `@Transactional` services |
| `org.ikigaidigital.adapter.in.web` | REST controller + mapper (implements generated `TimeDepositsApi`) |
| `org.ikigaidigital.adapter.out.persistence` | JPA entities, Spring Data repositories, persistence adapters implementing `port.out`, MapStruct entity→domain mapper |
| `org.ikigaidigital.config` | Spring beans for the framework-free domain |

## Workflow the agent must follow

1. **Characterize before you change.** Before touching behaviour, write or
   extend tests that pin the current behaviour.
2. **Small, atomic commits** using Conventional Commits
   (`feat:`, `fix:`, `refactor:`, `test:`, `build:`, `docs:`, `chore:`).
   One logical change per commit; the build must pass at every commit.
3. **Contract first** for API changes: edit the OpenAPI YAML, regenerate
   (`mvn generate-sources`), then implement.
4. **Assumptions** about ambiguous requirements go into a code comment
   starting with `ASSUMPTION:` at the place where the decision is made.
5. Run `mvn -f java/pom.xml verify` before declaring a task done
   (needs Docker for Testcontainers). If you cannot run it, say so explicitly.
6. Do not handle invalid input / exceptions beyond what is needed — the kata
   explicitly excludes it. Do not add speculative abstractions.

## Coding conventions

- Constructor injection only (`@RequiredArgsConstructor`), no field injection.
- Lombok for boilerplate: constructors, `@Getter` and a protected no-arg constructor on JPA entities, `@UtilityClass`.
  Never on the shared `TimeDeposit` class; no `@Data`/`@EqualsAndHashCode`/`@ToString` on JPA entities.
  Prefer records for value objects.
- Object-to-object mapping between layers uses MapStruct (`componentModel = spring`); no hand-written mappers.
- Money in the API and the database is `BigDecimal`/`NUMERIC(19,2)`;
  the legacy domain keeps `Double` — convert only at adapter boundaries.
- Test names: `methodOrBehaviour_condition_expectedResult` or a readable `@DisplayName`.
- AssertJ for assertions.

## Useful commands

```bash
mvn -f java/pom.xml test                   # fast unit + web-slice tests (no Docker)
mvn -f java/pom.xml verify                 # + *IT integration tests on Testcontainers
mvn -f java/pom.xml spring-boot:run        # starts Postgres via compose.yaml + the app
```
